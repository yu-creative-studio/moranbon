# 新しいお店にネット予約を導入する手順

前提：お店のサイトは YU DESIGN が作り、GitHub（yu-creative-studio）→ Cloudflare Pages で公開する。
Cloudflare と Google のアカウントは **お店の名義**。YU DESIGN はお店の Cloudflare に「メンバー」として招待してもらって作業する（パスワードは預からない）。

全体の流れ（目安：作業 3〜4 時間、お店の操作 15 分×2 回）

| # | 誰が | やること |
|---|---|---|
| 1 | YU | ルールのヒアリング → 設定ファイルを作る |
| 2 | YU | リポジトリを作り、ローカルで確認 |
| 3 | お店 | Cloudflare アカウントを作り、YU DESIGN を招待 |
| 4 | YU | Pages・D1・環境変数を設定 |
| 5 | お店＋YU | Apps Script（メール送信）を設定 |
| 6 | YU | 本番で一通り試す → お店に引き渡し |

---

## 1. ルールのヒアリング（YU）

LINE で次を聞き、`functions/shop.config.js` に入れる。分からないところはモランボンの値を仮で入れて、確認画面を見せながら決める。

- 店名・電話番号・住所・サイトURL・事業者名（個人情報ページ用）
- 営業時間、定休日（毎週◯曜／第◯◯曜／最終◯曜、祝日の扱い）
- ネットで受ける来店時刻（例：17:30〜19:30 の30分おき）、滞在時間（2時間制など）
- 当日予約の締め切り（来店の何分前まで）、ネットでのキャンセル期限（前日まで など）
- ネットで受ける最大人数（6名まで）、それ以上・宴会などの案内
- 卓の構成（4人卓・6人卓・それ以外）と、そのうちネットに出す数
- 予約通知を受け取るメールアドレス

> ネットに出せる卓は **4人卓・6人卓だけ**。2人卓中心のお店などは、作り込みが必要（別見積もり）。

## 2. リポジトリを作って確認（YU）

1. GitHub の yu-creative-studio に、お店用のリポジトリを作る（お店ごとに1つ）
2. モランボンのリポジトリの `template` ブランチから、次をコピーする
   - `reserve/`（`reserve.css` `shop.js` を含む）・`admin/`・`privacy/`・`functions/`・`setup/`・`.gitignore`
   - お店のサイト本体（`index.html`・`images/`）は、そのお店用に作ったもの
3. `functions/shop.config.js` を書き換える
4. ロゴを `images/logo.png` に置く（別の場所なら `brand.logo`）。色は `reserve/reserve.css` の `:root` を変える
5. `setup/migrations/0002_tables.sql` の最初の卓の一覧を、お店の卓に合わせる（あとで管理画面でも変えられる）
6. 確認する
   ```sh
   node setup/check-config.mjs                 # 文章・定休日・メールの例をお店に見せて確認してもらう
   node --test setup/dev/test.mjs
   node setup/dev/server.mjs --memory          # 予約 → キャンセル → 管理画面を一通り触る
   ```
7. main ブランチに push

## 3. お店に Cloudflare へ招待してもらう（お店）

LINE で送る手順：

1. https://dash.cloudflare.com/sign-up で、お店のメールアドレスでアカウントを作る（無料プラン）
2. 左下の **Manage Account → Members**（「メンバー」）を開き、**Invite**（招待）
3. メールアドレス：`yu.creative.design04@gmail.com`
4. 役割（Role）：**Developer Platform Admin**（表示が古い場合は **Workers Platform Admin**）
   - Pages・D1（データベース）・環境変数の設定ができる役割。お支払い情報は見られない
   - D1 が作れないなどで作業が止まったら、一時的に **Administrator** にしてもらう
5. 「Invite」を押したら、LINE で「招待しました」と連絡してもらう

> **Super Administrator（スーパー管理者）にはしてもらわない**。アカウントの持ち主はあくまでお店。

## 4. Cloudflare の設定（YU）

招待メールから参加 → ダッシュボード左上でお店のアカウントに切り替えてから作業する。

### 4-1. Pages プロジェクト
1. **Workers & Pages → Create → Pages → Connect to Git**
2. GitHub の連携で yu-creative-studio を選び、お店のリポジトリへのアクセスを許可（初回は Cloudflare の GitHub アプリのインストールが必要）
3. ビルド設定：Framework preset **None**、Build command **空欄**、Build output directory **/**、Production branch **main**
4. 独自ドメイン：**Custom domains** から追加（ドメインをエックスサーバーで取った場合は、エックスサーバー側で CNAME を設定）

### 4-2. D1（予約データ）
1. **Workers & Pages → D1 SQL Database → Create**。名前は `<お店の英字名>-reserve`
2. Console に `setup/migrations/0001_init.sql` → `0002_tables.sql` の順で貼り付けて実行（それぞれ1回だけ）
3. 試し用に、もう1つ `<お店の英字名>-reserve-preview` を作り、同じように実行する
4. Pages プロジェクト → **Settings → Bindings → Add → D1 database**
   - Variable name：`DB`
   - Production には `…-reserve`、Preview には `…-reserve-preview`（本番の予約と試しの予約が混ざらないように）

### 4-3. 環境変数（シークレット）
**Settings → Variables and Secrets** に、種類「Secret」で Production・Preview それぞれ追加。

| 名前 | 中身 |
|---|---|
| `ADMIN_PASSWORD` | 管理画面のパスワード（8文字以上。10文字以上がおすすめ。お店に渡す） |
| `SESSION_SECRET` | 32文字以上のランダムな文字列 |
| `GAS_SECRET` | 24文字以上のランダムな文字列（手順5でも使う） |
| `GAS_WEBHOOK_URL` | 手順5で作る Apps Script の URL（…/exec）。あとで入れる |

ランダムな文字列は `openssl rand -base64 36` で作る。**お店ごとに必ず新しく作る**（モランボンの値を使い回さない）。
設定を変えたら **Deployments → 最新 → Retry deployment** で反映。

## 5. メール送信（Apps Script）

Apps Script は「実行する人の Gmail から送る」仕組みなので、**デプロイと承認だけはお店のアカウントで**やってもらう。
コードと設定は YU が入れる（シークレットを LINE で送らずに済む）。

**お店（LINE で手順を送る）**
1. お店の Google アカウントで https://script.google.com → **新しいプロジェクト**
2. 右上の **共有** から `yu.creative.design04@gmail.com` を **編集者** で追加 → LINE で連絡

**YU**
3. `setup/gas/Code.gs` の中身をそのまま貼り付けて保存（お店ごとに書き換える必要はない）
4. **プロジェクトの設定 → スクリプト プロパティ** に追加
   - `GAS_SECRET`：手順4-3 と同じ値
   - `SITE_URL`：お店のサイトの URL（最後の / なし）
   - `SHOP_EMAIL`：予約通知を受け取るアドレス（省略するとお店のアカウント宛）

**お店（LINE で手順を送る。画面の写真つき）**
5. **デプロイ → 新しいデプロイ → 種類：ウェブアプリ**、「次のユーザーとして実行：自分」「アクセスできるユーザー：全員」→ **デプロイ**
6. 「アクセスを承認」→ お店のアカウントを選ぶ →「詳細」→「（安全ではないページ）に移動」→「許可」
7. 表示された **ウェブアプリの URL** を LINE で送ってもらう
8. 上の関数の選択で **setupTrigger** を選んで **実行**（前日リマインドが毎日10時台に動くようになる）
9. 続けて **testMail** を実行 → お店にテストメールが届くか確認

**YU**
10. 届いた URL を Cloudflare の `GAS_WEBHOOK_URL` に入れて、Retry deployment
11. 共有の編集者から自分を外すかどうかは、保守の契約に合わせる（`販売時の決めごと.md`）

## 6. 本番で試して引き渡す（YU）

- [ ] `node setup/check-config.mjs` の内容（ルールの文章・定休日）をお店に確認してもらった
- [ ] `/privacy/` の事業者名・制定日をお店に確認してもらった
- [ ] 自分で予約 → 確認メール → お店への通知 → キャンセル → キャンセルメール が届く
- [ ] 翌日の予約を入れて、前日リマインドが届く（次の日の10時台）
- [ ] 定休日・当日の締め切り・満席がそのとおりに表示される
- [ ] 管理画面：ログイン、電話予約の入力、取り消し、休業の設定、卓の設定を、お店の人に実際に触ってもらった
- [ ] 試した予約を管理画面から取り消した
- [ ] お店に渡す：管理画面の URL とパスワード、「予約が入ったらメールが来る」「止めたい日は休業・貸切タブ」の説明
- [ ] サイト・Instagram のプロフィールに `/reserve/` のリンクを置く

## 困ったとき

| 症状 | 確認するところ |
|---|---|
| 予約画面に「お店の情報を読み込めませんでした」 | `shop.config.js` の間違い（`node setup/check-config.mjs`）、D1 の Binding |
| 「予約データベース（D1）が接続されていません」 | Pages の Bindings に `DB` があるか、Retry deployment したか |
| メールが届かない | `GAS_WEBHOOK_URL`・`GAS_SECRET` が両方で同じか、Apps Script の「実行数」にエラーがないか、迷惑メールフォルダ |
| 前日リマインドが届かない | `setupTrigger` を実行したか、`SITE_URL` が正しいか |
| 管理画面に入れない | `ADMIN_PASSWORD`・`SESSION_SECRET` を設定したか。5回間違えると15分待つ |
